# Journal — M2 VIP subsystem audit

**Date:** 2026-08-09  
**Stage:** 06 — Verification and Repository Rationalization  
**Milestone:** M2

## Trigger

After removal of legacy runtime and Telegram transport experiments, root inventory still contained `vip/`, a pre-FATHER subsystem mixing anonymity, generated personas, temporary phone numbers, evidence handling and commercial tiers.

## Decision

Treat `vip/` as legacy implementation. Preserve only reusable engineering requirements in documentation, especially evidence hashing/provenance/chain-of-custody concepts. Remove the code from the active repository after dependency review and then verify clean CI.

## WHY

The current FATHER architecture requires narrow components justified by explicit requirements. `vip/` is a monolithic historical product concept with no current approved dependency.

The evidence module has useful ideas, but direct reuse would import weak restart semantics, mutable custody files, hard-coded actors and mixed sanitization/evidence responsibilities.

## Preserved knowledge

- originals are immutable;
- calculate SHA-256 on original bytes before transformation;
- all normalization/transcription/OCR/translation outputs are derivatives;
- custody/audit events identify actor/tool/run and reason;
- future OPSEC capabilities require separate requirements, threat/policy review and acceptance tests.

Full analysis: `docs/06_verification/14_VIP_LEGACY_AUDIT.md`.

## Next action

Delete `vip/` files from active tree and require green clean-checkout CI before marking the cleanup PASS.
